02 · React essentials · 15 min

Hooksを「役割」で捉える

APIを丸暗記する必要はありません。今回使う4つを「何のために存在するか」で区別します。

useState

画面に反映したい値を持ちます。値を更新すると再レンダーされます。

const [input, setInput] = useState("");
setInput("こんにちは"); // 画面の入力欄も更新

useRef

再レンダーせず保持したい箱です。非同期処理から最新値を読む用途にも使います。

const chatIdRef = useRef(chatId);
chatIdRef.current = nextChatId; // 画面更新は起こさない

useEffect

レンダー外の世界と同期します。通信、購読、DOM、ref同期などです。

useEffect(() => {
  chatIdRef.current = chatId;
}, [chatId]);

Context

離れた子孫へ共通の値と操作を配る仕組みです。Providerが供給し、hookが取得します。

<ChatbotContext.Provider value={value}>
  {children}
</ChatbotContext.Provider>

Providerは「巨大なstate置き場」ではない

Providerの本質は、複数のUIが同じチャット状態と操作を共有するための公開APIです。 入力欄は sendMessage を使い、メッセージ一覧は messages を読みます。 UI側は通信方法や保存方法を知る必要がありません。

判断基準

値の変更を画面へ反映したいならstate。画面更新なしで処理中の最新値を参照したいならref。 外部との同期ならeffect。離れた子へ同じ機能を公開するならContextです。

30秒チェック

送信中かどうかを保持するなら state と ref のどちら？

state。送信中表示やボタンのdisabled状態を更新したいからです。今回はAI SDKの status がこのstateを管理します。

非同期コールバックから「現在開いているchatId」を読むためにrefを使うのはなぜ？

コールバック作成時点の古い値（stale closure）ではなく、実行時点の最新値を読みたいからです。本体の chatRef も同じ目的を持ちます。

03 · Next.js boundary · 10 min

ブラウザとサーバーを分ける

App Routerでは、コンポーネントは標準でServer Componentです。 Hooksやブラウザ操作が必要なファイルだけ、先頭に "use client" を付けます。

Client Component

  • useState や useChat を使う
  • クリックやフォーム入力を処理する
  • 秘密鍵やDBへ直接アクセスしない

Server Component / Route Handler

  • DBから初期データを読む
  • AI Gatewayの認証情報を扱う
  • app/api/**/route.ts でHTTPを処理する

今回の境界

page.tsxServer：DBから初期履歴
→
ChatbotProviderClient：useChatとContext
→
route.tsServer：AI呼び出しとDB保存
セキュリティ境界でもある

AI_GATEWAY_API_KEY は NEXT_PUBLIC_ を付けず、Route Handlerだけで利用します。 Client Componentへimportしたファイルに秘密情報やDB接続を置いてはいけません。

04 · First working chat · 55 min

まずモックでストリームを通す

認証やモデルの問題を切り離し、UI Message Streamが端から端まで流れる状態を先に作ります。 以下の3ファイルは、その時点の完全な内容です。

1. Route Handlerを作る

src/app/api/chat/route.ts を作成します。

src/app/api/chat/route.ts
import {
  createUIMessageStream,
  createUIMessageStreamResponse,
  generateId,
  type UIMessage,
} from "ai";

const sleep = (ms: number) =>
  new Promise<void>((resolve) => setTimeout(resolve, ms));

export async function POST(request: Request) {
  const { messages }: { messages: UIMessage[] } = await request.json();

  const latestText = messages
    .at(-1)
    ?.parts.filter((part) => part.type === "text")
    .map((part) => part.text)
    .join("");

  const answer =
    `「${latestText ?? ""}」を受け取りました。` +
    "これはAIを呼ばずに返しているストリーミングモックです。";

  const stream = createUIMessageStream({
    originalMessages: messages,
    generateId,
    execute: async ({ writer }) => {
      const textPartId = generateId();
      writer.write({ type: "text-start", id: textPartId });

      for (const character of answer) {
        if (request.signal.aborted) {
          writer.write({ type: "abort" });
          return;
        }

        writer.write({
          type: "text-delta",
          id: textPartId,
          delta: character,
        });
        await sleep(24);
      }

      writer.write({ type: "text-end", id: textPartId });
    },
  });

  return createUIMessageStreamResponse({ stream });
}
ここで重要なのはSSEの形式

単なる文字列のHTTPストリームではありません。useChat が解釈できる text-start → text-delta → text-end のUI Message Streamを返しています。

2. ChatbotProviderを作る

src/components/chatbot-provider.tsx を作成します。

src/components/chatbot-provider.tsx
"use client";

import { useChat } from "@ai-sdk/react";
import {
  DefaultChatTransport,
  type ChatStatus,
  type UIMessage,
} from "ai";
import {
  createContext,
  type Dispatch,
  type ReactNode,
  type SetStateAction,
  useCallback,
  useContext,
  useMemo,
  useState,
} from "react";

type ChatbotContextValue = {
  messages: UIMessage[];
  status: ChatStatus;
  error: Error | undefined;
  clearError: () => void;
  input: string;
  setInput: Dispatch<SetStateAction<string>>;
  sendMessage: () => Promise<void>;
  stop: () => Promise<void>;
};

const ChatbotContext = createContext<ChatbotContextValue | null>(null);

export function ChatbotProvider({ children }: { children: ReactNode }) {
  const [input, setInput] = useState("");

  const transport = useMemo(
    () => new DefaultChatTransport({ api: "/api/chat" }),
    [],
  );

  const {
    messages,
    status,
    error,
    clearError,
    sendMessage: sendChatMessage,
    stop,
  } = useChat({
    id: "learning-chat",
    transport,
  });

  const sendMessage = useCallback(async () => {
    const text = input.trim();
    if (!text || status !== "ready") return;

    setInput("");
    await sendChatMessage({ text });
  }, [input, sendChatMessage, status]);

  const value = useMemo<ChatbotContextValue>(
    () => ({
      messages,
      status,
      error,
      clearError,
      input,
      setInput,
      sendMessage,
      stop,
    }),
    [messages, status, error, clearError, input, sendMessage, stop],
  );

  return (
    <ChatbotContext.Provider value={value}>
      {children}
    </ChatbotContext.Provider>
  );
}

export function useChatbot() {
  const context = useContext(ChatbotContext);

  if (context === null) {
    throw new Error("useChatbot must be used within ChatbotProvider");
  }

  return context;
}

このProviderがしていること

  1. useState で入力文字列を管理する。
  2. DefaultChatTransport にAPIの場所を教える。
  3. useChat からメッセージ・状態・操作を受け取る。
  4. アプリ固有の「空文字を送らない」「送ったら入力を消す」をラップする。
  5. Context経由で子コンポーネントへ公開する。

              <p className="mt-2 text-sm text-zinc-500">

              </p>
            </div>
          </div>

            >
              送信
            </button>
          )}
        </div>
      </form>
    </section>
  );
}

05 · Read useChat · 20 min

useChat を状態機械として読む

useChat は「AIを呼ぶhook」ではありません。チャットUIの状態を持ち、 transportへHTTP通信を委譲し、返ってきたイベントでメッセージを更新するhookです。

statusの遷移

ready送信可能
→
submitted応答開始待ち
→
streamingchunk受信中
→
ready / error完了または失敗

messages

画面表示用の UIMessage[]。本文は content ではなく parts にあります。

sendMessage({ text })

ユーザーメッセージを追加し、transportにリクエストを開始させます。

stop()

現在のクライアントリクエストをAbortします。分散環境のサーバー処理停止とは別問題です。

DefaultChatTransport

送信先、headers、credentials、request body、再接続先など、HTTPの詳細を担当します。

なぜメッセージは parts なのか

アシスタントの出力はテキストだけとは限りません。推論、ファイル、出典、ツール入力・結果、 独自data partなどを同じメッセージへ順序付きで格納するためです。 今回は part.type === "text" だけ表示します。

Providerが薄いラッパーを作る理由

UIへ生の sendChatMessage を渡さず、sendMessage() で包みました。 これにより、空文字チェック・入力クリア・アプリ固有コマンド・利用制限などをUIから分離できます。 本体も同じ発想で、圧縮コマンドや履歴更新を追加しています。

理解確認

なぜinputはuseChatではなくuseStateで持つ？

AI SDK v6の useChat はメッセージと通信状態を管理しますが、フォーム入力の状態はアプリ側の責務だからです。

なぜProvider内でtransportをuseMemoしている？

レンダーごとに新しいtransportインスタンスを作らず、同じ通信設定を安定して使うためです。本体では変化するbodyやheadersをref経由で読むことで、transportの再生成を避けています。

モックを実AIへ差し替える

UIとProviderは変更しません。サーバーの生成部分だけを差し替えます。 この交換可能性が、境界を分けた効果です。

2. Route Handlerを置き換える

src/app/api/chat/route.ts
import {
  convertToModelMessages,
  createUIMessageStream,
  createUIMessageStreamResponse,
  generateId,
  streamText,
  type UIMessage,
} from "ai";

export const maxDuration = 30;

const sleep = (ms: number) =>
  new Promise<void>((resolve) => setTimeout(resolve, ms));

function createMockResponse(messages: UIMessage[], signal: AbortSignal) {
  const answer =
    "モックモードです。USE_MOCK_AI=false にすると実際のモデルへ接続します。";

  const stream = createUIMessageStream({
    originalMessages: messages,
    generateId,
    execute: async ({ writer }) => {
      const textPartId = generateId();
      writer.write({ type: "text-start", id: textPartId });

      for (const character of answer) {
        if (signal.aborted) {
          writer.write({ type: "abort" });
          return;
        }

        writer.write({
          type: "text-delta",
          id: textPartId,
          delta: character,
        });
        await sleep(24);
      }

      writer.write({ type: "text-end", id: textPartId });
    },
  });

  return createUIMessageStreamResponse({ stream });
}

export async function POST(request: Request) {
  const { messages }: { messages: UIMessage[] } = await request.json();

  if (process.env.USE_MOCK_AI === "true") {
    return createMockResponse(messages, request.signal);
  }

  const model = process.env.AI_MODEL;
  if (!model) {
    return new Response("AI_MODEL is not configured", { status: 500 });
  }

  const result = streamText({
    model,
    system:
      "あなたは簡潔で親切な学習アシスタントです。回答は日本語で返してください。",
    messages: await convertToModelMessages(messages),
    abortSignal: request.signal,
  });

  return result.toUIMessageStreamResponse({
    originalMessages: messages,
    generateMessageId: generateId,
  });
}

  2. USE_MOCK_AI=false に変えて再起動し、実AIが応答する。

Gateway接続で失敗したとき
  • 401 / 認証エラー：キーまたはOIDCトークンを確認。値そのものはログへ出さない。
  • Free tier users do not have access to this model：無料枠で使えないモデルです。AI_MODEL=openai/gpt-5.4-mini に変えて dev server を再起動します。旗艦モデルが必要なら Vercel で有料クレジットを購入します。
  • モデルが見つからない：Free Tier models で現在利用可能なIDへ AI_MODEL を変更。
  • 学習を続けたい：USE_MOCK_AI=true に戻す。UI・DBの章には影響しません。
停止ボタンの限界

この簡易版はブラウザ接続のabortを request.signal へ伝播させます。 本体は接続から独立した再開可能ストリームを使うため、別のstop APIとRedis通知で生成を止めます。 「接続を切る」と「サーバー上の処理を止める」が同義でない構成は発展領域です。

07 · Persistence · 55–75 min

SQLiteへ保存し、再読み込みで復元する

UI表示に使う UIMessage を、partsを保ったまま保存します。 chats と messages を分け、単一チャットでもデータモデルの境界を作ります。

このSQLite構成はローカル学習専用

ローカルファイルへ保存するため、通常のVercel Functionsへそのままデプロイして永続化することはできません。 デプロイ時はNeonなどのマネージドDBへ置き換えます。ここではDB設計と保存フローの理解を優先します。

2. スキーマを書く

src/db/schema.ts を作成します。

src/db/schema.ts
import type { UIMessage } from "ai";
import { index, integer, sqliteTable, text } from "drizzle-orm/sqlite-core";

export const chats = sqliteTable("chats", {
  id: text("id").primaryKey(),
  createdAt: integer("created_at", { mode: "timestamp_ms" }).notNull(),
  updatedAt: integer("updated_at", { mode: "timestamp_ms" }).notNull(),
});

export const messages = sqliteTable(
  "messages",
  {
    id: text("id").primaryKey(),
    chatId: text("chat_id")
      .notNull()
      .references(() => chats.id, { onDelete: "cascade" }),
    sequence: integer("sequence").notNull(),
    role: text("role").$type<UIMessage["role"]>().notNull(),
    parts: text("parts", { mode: "json" })
      .$type<UIMessage["parts"]>()
      .notNull(),
  },
  (table) => [
    index("messages_chat_sequence_idx").on(table.chatId, table.sequence),
  ],
);

なぜcontentではなくpartsを保存する？

AI SDK v6のUIメッセージは、テキスト以外のツール結果やファイルもpartsとして持てるからです。 本体の CustomUIMessage も、この拡張可能な形を使っています。

6. 保存・取得関数を作る

src/db/chat-store.ts を作成します。

src/db/chat-store.ts
import { asc, eq } from "drizzle-orm";
import type { UIMessage } from "ai";
import { db } from "./index";
import { chats, messages } from "./schema";

export const LEARNING_CHAT_ID = "learning-chat";

export function loadMessages(chatId: string): UIMessage[] {
  return db
    .select({
      id: messages.id,
      role: messages.role,
      parts: messages.parts,
    })
    .from(messages)
    .where(eq(messages.chatId, chatId))
    .orderBy(asc(messages.sequence))
    .all();
}

export function saveMessages(chatId: string, nextMessages: UIMessage[]) {
  const now = new Date();

  db.transaction((tx) => {
    tx.insert(chats)
      .values({
        id: chatId,
        createdAt: now,
        updatedAt: now,
      })
      .onConflictDoUpdate({
        target: chats.id,
        set: { updatedAt: now },
      })
      .run();

    tx.delete(messages).where(eq(messages.chatId, chatId)).run();

    if (nextMessages.length === 0) return;

    tx.insert(messages)
      .values(
        nextMessages.map((message, sequence) => ({
          id: message.id,
          chatId,
          sequence,
          role: message.role,
          parts: message.parts,
        })),
      )
      .run();
  });
}
簡易版として割り切った点

毎回そのチャットのmessagesを削除して全件挿入しています。理解しやすさを優先した方式です。 本番では差分保存、同時更新制御、soft delete、失敗時の整合性、ユーザー権限が必要です。

7. Providerへ初期メッセージと最終発言送信を追加

src/components/chatbot-provider.tsx を以下の完成形へ置き換えます。

src/components/chatbot-provider.tsx
"use client";

import { useChat } from "@ai-sdk/react";
import {
  DefaultChatTransport,
  type ChatStatus,
  type UIMessage,
} from "ai";
import {
  createContext,
  type Dispatch,
  type ReactNode,
  type SetStateAction,
  useCallback,
  useContext,
  useMemo,
  useState,
} from "react";

type ChatbotContextValue = {
  messages: UIMessage[];
  status: ChatStatus;
  error: Error | undefined;
  clearError: () => void;
  input: string;
  setInput: Dispatch<SetStateAction<string>>;
  sendMessage: () => Promise<void>;
  stop: () => Promise<void>;
};

const ChatbotContext = createContext<ChatbotContextValue | null>(null);

type ChatbotProviderProps = {
  children: ReactNode;
  chatId: string;
  initialMessages: UIMessage[];
};

export function ChatbotProvider({
  children,
  chatId,
  initialMessages,
}: ChatbotProviderProps) {
  const [input, setInput] = useState("");

  const transport = useMemo(
    () =>
      new DefaultChatTransport({
        api: "/api/chat",
        prepareSendMessagesRequest: ({ id, messages }) => ({
          body: {
            chatId: id,
            message: messages.at(-1),
          },
        }),
      }),
    [],
  );

  const {
    messages,
    status,
    error,
    clearError,
    sendMessage: sendChatMessage,
    stop,
  } = useChat({
    id: chatId,
    messages: initialMessages,
    transport,
  });

  const sendMessage = useCallback(async () => {
    const text = input.trim();
    if (!text || status !== "ready") return;

    setInput("");
    await sendChatMessage({ text });
  }, [input, sendChatMessage, status]);

  const value = useMemo<ChatbotContextValue>(
    () => ({
      messages,
      status,
      error,
      clearError,
      input,
      setInput,
      sendMessage,
      stop,
    }),
    [messages, status, error, clearError, input, sendMessage, stop],
  );

  return (
    <ChatbotContext.Provider value={value}>
      {children}
    </ChatbotContext.Provider>
  );
}

export function useChatbot() {
  const context = useContext(ChatbotContext);

  if (context === null) {
    throw new Error("useChatbot must be used within ChatbotProvider");
  }

  return context;
}

送信するのは最後のメッセージだけになりました。サーバーがDBから過去履歴を読み、 最後のユーザーメッセージを追加します。本体の selectRequestFrontier と同じ方向性です。

8. APIをDB対応の完成形へ置き換える

src/app/api/chat/route.ts
import {
  convertToModelMessages,
  createUIMessageStream,
  createUIMessageStreamResponse,
  generateId,
  streamText,
  type UIMessage,
  validateUIMessages,
} from "ai";
import { loadMessages, saveMessages } from "@/db/chat-store";

export const maxDuration = 30;

type ChatRequest = {
  chatId: string;
  message: UIMessage;
};

const sleep = (ms: number) =>
  new Promise<void>((resolve) => setTimeout(resolve, ms));

function createMockResponse(
  chatId: string,
  messages: UIMessage[],
  signal: AbortSignal,
) {
  const answer =
    "DB対応モックです。この応答が完了するとSQLiteへ保存されます。";

  const stream = createUIMessageStream({
    originalMessages: messages,
    generateId,
    execute: async ({ writer }) => {
      const textPartId = generateId();
      writer.write({ type: "text-start", id: textPartId });

      for (const character of answer) {
        if (signal.aborted) {
          writer.write({ type: "abort" });
          return;
        }

        writer.write({
          type: "text-delta",
          id: textPartId,
          delta: character,
        });
        await sleep(24);
      }

      writer.write({ type: "text-end", id: textPartId });
    },
    onFinish: ({ messages: completedMessages, isAborted }) => {
      if (!isAborted) saveMessages(chatId, completedMessages);
    },
  });

  return createUIMessageStreamResponse({ stream });
}

export async function POST(request: Request) {
  const body = (await request.json()) as Partial<ChatRequest>;
  const { chatId, message } = body;

  if (!chatId || !message) {
    return new Response("chatId and message are required", { status: 400 });
  }

  const previousMessages = loadMessages(chatId);
  const messages = await validateUIMessages({
    messages: [...previousMessages, message],
  });

  // AIが失敗・中断してもユーザー発言は残す。
  saveMessages(chatId, messages);

  if (process.env.USE_MOCK_AI === "true") {
    return createMockResponse(chatId, messages, request.signal);
  }

  const model = process.env.AI_MODEL;
  if (!model) {
    return new Response("AI_MODEL is not configured", { status: 500 });
  }

  const result = streamText({
    model,
    system:
      "あなたは簡潔で親切な学習アシスタントです。回答は日本語で返してください。",
    messages: await convertToModelMessages(messages),
    abortSignal: request.signal,
  });

  return result.toUIMessageStreamResponse({
    originalMessages: messages,
    generateMessageId: generateId,
    onFinish: ({ messages: completedMessages, isAborted }) => {
      if (!isAborted) saveMessages(chatId, completedMessages);
    },
  });
}
保存タイミングを2回に分けた理由

生成開始前にユーザーメッセージまで保存し、完了後にアシスタントメッセージを含む全体を保存します。 生成エラー時に「送った質問まで消える」ことを避けます。本体はさらにoperation IDやfinalizerで整合性を守ります。

コードを閉じて説明してみる

次の5問へ、コードを見ずに答えてください。答えられない箇所だけ該当章へ戻れば十分です。

Q1. ChatbotProviderは何を集約し、UIから何を隠している？

チャット状態、入力、送信・停止操作を集約し、transport、APIの場所、送信前後のアプリ固有処理をUIから隠しています。 本体ではさらに認証、agent/model、履歴切替、compaction、tools、canvas、embedを集約します。

Q2. useStateとuseRefをどう使い分ける？

変更を画面へ反映する値はstate。レンダーを起こさず保持する値や、非同期コールバックから最新値を読む箱はrefです。

Q3. Client ComponentとRoute Handlerの境界はどこ？

Hooksとユーザー操作はClient Component。秘密情報、モデル呼び出し、DBアクセスはサーバーのRoute HandlerまたはServer Componentです。

Q4. 送信してから文字が表示されるまで、何が起きる？

sendMessageがUIMessageを追加し、transportがPOSTし、Route HandlerがModelMessageへ変換して生成を開始します。 UI Message StreamのchunkをuseChatが読み、messagesを更新するためReactが再レンダーします。

Q5. DBから復元した履歴は、どこでuseChatへ入る？

Server Componentのpage.tsxがDBから読み、ProviderのinitialMessages propを経由して useChat({ messages }) へ渡します。

次に本体で試す読解課題

  1. bodyRef を更新するeffectと、transportから読む箇所を線で結ぶ。
  2. sendMessage wrapperが生の chat.sendMessage に足している処理を列挙する。
  3. openChat 内のすべての isLatestSwitch を外した場合のバグを想像する。
  4. contextValue の項目を「AI SDK」「composer」「embed」「canvas」「business rule」に分類する。
